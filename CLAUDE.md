# StuntsReloaded

A browser remake of Stunts (1990). The driving simulation is a faithful, bit-exact port of the original game code. Rendering is new: the original low-poly geometry drawn with Three.js. It loads the original data files from the player's own copy (folder or .zip, kept in the browser), else `game-ms/` or `game/` (never commit them), else restunts on GitHub (`src/store.js`, `src/start.js`). To fill `game/`: `mkdir -p game && curl -L https://github.com/4d-stunts/restunts/archive/refs/heads/master.tar.gz | tar xz -C game --strip-components=2 restunts-master/stunts && mv game/game.exe game/GAME.EXE`. To fill `game-ms/`: unzip https://pigsgrame.de/downloads/4DSPORTS.ZIP into it.

## Two builds

The game exists in two 1.1 releases that drive differently, and both are ported (`src/version.js`):

- `bb`: Broderbund Stunts 1.1 (Feb 1991), restunts' `game.exe`, in `game/`. The ports were written from its disassembly.
- `ms`: Mindscape 4D Sports Driving 1.1 (Dec 1990), in `game-ms/`: the build [playstunts](https://github.com/ACatWithEbola/playstunts) reconstructs, and the one the page plays when it has a copy. Its executable comes in pieces that `src/exe.js` joins and unpacks.

The build is fixed before the simulation modules load, because they resolve addresses at import: `src/start.js` (the page's entry) sets `globalThis.STUNTS_VERSION` from the executable it found, then imports `main.js`; the tools take the `STUNTS_VERSION=ms` environment variable (default `bb`). Each build has its own address tables (`procs.js` / `procs-ms.js`, `dseg-labels.js` / `dseg-labels-ms.js`); the Mindscape image is loaded at segment 0x10DD so that DGROUP is at the same address in both. Its CARSTATE has no `car_whlWorldCrds2` (GAMESTATE is 0x430 bytes), its replay header no frame rate (24 bytes), and it has no 10 fps setting (`fps()` in structs.js).

A port branches on `MS` where the builds differ. A global that only one build has throws when the other touches it (`A.name`).

playstunts compatibility: on the Mindscape build the page also sets `rules.playstunts` (version.js), which makes the ports do the two things playstunts does differently from the original (player.js: a stopped car across a wall is moved clear; a stopped car's wheel angles are kept from its last moving tick). The tools leave it off, so traces compare against the original; `tools/test-playstunts.mjs` checks the rules themselves and the file formats (`src/interop.js`: `.HIG` high scores, playstunts' backup JSON). playstunts is GPL-3.0: read it, do not copy from it.

Run it with `python3 -m http.server` in the repo root, then open http://localhost:8000. There is no build step: the code is plain ES modules, and Three.js is vendored in `vendor/` (the few addons in `vendor/addons/` have their `'three'` imports rewritten to relative paths).

## Architecture

- `src/mem.js` emulates real-mode memory in one flat `M` (1.1 MB). GAME.EXE is loaded at segment 0x1000, so its data segment (DGROUP) sits at linear `DS` = 0x3B770 and every original global lives at its original address. `A.name` is a global's linear address, and `G.name`/`U.name` give signed/unsigned scalar access. Far pointers are seg:off pairs in memory (`farptr`, `setFarptr`, `farptrAt`). The far heap is a bump allocator (`farAlloc`) at 0x50000.
- `src/structs.js`: original struct layouts (CARSTATE, GAMESTATE, SIMD, ...) as views over memory; `state`, `simd_player`, etc.
- `src/x86.js` is an 8086 interpreter. `src/engine.js` runs original functions (`callOrig(name, ...args)`) and replaces them with JS ports (`hook(name, fn)`). Both share `M`, so ported and original code can call each other freely. `src/procs.js` holds the function addresses, generated by `tools/procmap.mjs`.
- `src/race.js`: boot, load a track or replay, `setupRace`, `step(input)`. `replayBuild(bytes)` tells which build recorded a replay. Input byte: 1 accelerate, 2 brake, 4 right, 8 left (as in the original's key table, get_kb_or_joy_flags), 0x10 shift up, 0x20 shift down.
- `src/math.js`, `gamestate.js`, `track.js`, `car.js`, `player.js`, `surface.js`: the ported simulation. `src/ports.js` lists the modules enabled in the game; a module is added there only after the combined trace of all listed modules passes.
- `src/tweaks.js`: the two optional gameplay changes (menu options, off by default): steering assist (replaces upd_statef20_from_steer_input; analog stick deflection in bits 6-7 of the input byte) and car fragility (scaled crash thresholds in update_player_state and car_car_speed_adjust_maybe, player's car only; below 100 % the car can survive what always wrecks the original). The ports branch on `tweaks` only where it is non-default, so the defaults stay bit-exact. `setTweaks` is called per race (main.js) and by `loadReplay`, from the 8-byte trailer tweaked replays carry after their inputs. Tweak code is not a port: it need not match anything, but it must depend only on emulated memory (replays and their snapshots must reproduce it).
- `src/render.js` builds the Three.js scene: merged track geometry, the tone curve (palette colours come out unchanged), and the original's patterned materials as alpha-to-coverage gratings (`patterned`). `src/fx*.js` is the optional "Enhanced graphics" mode, rendering only: `fx.js` (sky, procedural surfaces by original paint index, cascaded shadows, light balance), `fx-post.js` (the HDR target, quarter-resolution bloom and the single output pass), `fx-effects.js` (skid marks, smoke, dust, crash fire, read from CARSTATE), `fx-scenery.js` (3D distant scenery per scenery byte, clouds). A sunlit level surface must show its palette colour (SUN and HEMI in fx.js): check with a screenshot's pixels after touching lights or tone mapping.
- `src/res.js` / `src/files.js` / `src/store.js`: decompression, RES archives, 3D shapes; far-heap placement; the copies of the game (served, cached in IndexedDB, .zip) and which build each is.

## Porting rules

The whole simulation is ported (all modules in `src/ports.js`), so the game never runs original code. `node tools/profile-orig.mjs` must report none for boot, setup and race. Any change to a port, or a newly ported function, must stay diff-verified. `node tools/trace-all.mjs` checks all ports together against the original:

1. Reference sources are in `ref/restunts` (a git-ignored clone of github.com/4d-stunts/restunts). `tools/asm.sh <proc>` prints the original asm (asmorig). `ref/restunts/src/restunts/c/*.c` contains partial C ports; they are helpful but sometimes wrong (e.g. vector_op_unk's shifts, mat_rot_zxy's caches). **The asm is the truth.**
   - The Mindscape build has no listing. `node tools/vermap.mjs game-ms --diff <proc>[..<end proc>] [--loose]` shows what differs from the Broderbund code, disassembled with restunts' names (`--loose` ignores which stack slot a local is in; the report ends with the constants and operands that changed inside matching instructions: read those too). `--dis <proc>` and `--at <hex address>,<count>` print Mindscape code. Typical differences: `x / 2^n` rounded toward zero (`sdiv2`, `shalf` in mem.js) where Broderbund shifts, no 10 fps code, other thresholds. After changing address tables by hand (`tools/vermap-ms.json`), regenerate with `--write`.
2. Port with C semantics: `int` is 16-bit, `long` is 32-bit. Use `s16`, `u16`, `s8` and the typed memory accessors (`rsw`, `ww`, ...); stores wrap automatically. Mind `cbw` (signed) vs `sub ah,ah` (unsigned) byte loads. The original's divide-overflow handler resumes mid-instruction, so use `idiv` from math.js (it throws on overflow). In memory, near pointers are DS offsets (`DS + rw(p)` gives the linear address); JS function arguments are always linear. Locals whose address is taken go on the scratch stack (`frame`, `alloca`, `local`) in memory, never in JS objects.
3. Keep side effects on globals identical, including caches and scratch globals: the diff compares all of DGROUP and the far heap.
4. Cross-function calls go through the call layer, `call.name(...)` from `src/calls.js`. It runs the JS port if enabled, else the original. Every function needs a signature in `calls.SIGS` (modules add missing ones with `defineSigs`): `w` word, `n` near pointer, `l` long, `f` far pointer; JS always sees pointers as linear addresses. Values returned from originals are raw `dx:ax`, so mask or sign them as the original would. JS ports receive `w` args as unsigned 16-bit, so apply `s16` wherever the original treats them as signed. A port module calls `provide({ fn, ... })` at import time and exports `PORTS` (the names that are verified). Math functions from math.js may be imported and called directly.
5. **Uninitialized stack reads.** update_player_state reads locals it never wrote (var_16, var_140someWhlData). On DOS they held residue from earlier calls and timer interrupts, i.e. they were nondeterministic. We define them as zero: the engine probes the original after its prologue and zeroes the frame (engine.js `installStubs`), and the JS port does the same.
   - JS ports also keep the original's stack depth: the `call` proxy pushes args and a return-address slot for JS-to-JS calls, and `src/stack.js` can write exact residue. Since the zero-init, exact residue is no longer needed for the known cases, and on the Mindscape build (other frames and call sites) it is not written at all (`origStack` is inert there).
   - If a trace fails only in combination with other modules, suspect another uninitialized read before anything else.
   - Test ports through their hook (`enable([name]); callOrig(name, ...)`).
6. Verify with `tools/difftest.mjs` (`fuzz`/`compare` run JS vs original from the same memory snapshot) and `tools/trace.mjs` (a full race scenario with the port hooked vs pure original, compared every frame). `tools/test-*.mjs` hold the tests; run them with `node`.

## Tools

- `node tools/world.mjs [X.RPL]`: runs a replay through the simulation and prints a summary.
- Every tool below runs on the Broderbund build; prefix `STUNTS_VERSION=ms` for the Mindscape one. A simulation change must pass on both.
- `node tools/trace-all.mjs`: every enabled port vs the original, all scenarios (about 1 min), including an opponent's lap on every other `.TRK` in `game/` and `game-ms/`. Run it after any simulation change.
- `node tools/profile-orig.mjs`: which original functions still run in the interpreter (should be none).
- `node tools/test-{math,gamestate,track,car,player,surface,misc}.mjs`: per-module fuzz tests.
- `node tools/test-tweaks.mjs`: the tweaks' own guarantees (nothing changes before the original's crash, never wrecked at 0 %, assisted steering stays within the grip, tweaked replays reproduce). Run it after touching `src/tweaks.js` or a tweak branch in a port.
- `STUNTS_VERSION=ms node tools/test-playstunts.mjs`: playstunts' rules (nothing changes until a car is at rest, the wall case, the kept wheel angles) and the traded file formats.
- `node tools/browse.mjs <url> <steps-json>`: drives headless Chromium (clicks, keys, eval, screenshots). `window.stunts` exposes debug helpers, e.g. `stunts.ff(n)` to fast-forward and `stunts.seek(frame)` in a replay. URL flags: `?feed=DEFAULT.RPL` races with a replay's inputs (and its car), `?skip=N` jumps the demo ahead, `?auto` holds the accelerator, `?original` uses the original code, `?enhanced` turns on enhanced graphics, `?version=bb|ms` picks the build. `BROWSE_GPU=1` renders on the machine's GPU with the frame rate uncapped (to measure: F shows the frame rate), `BROWSE_SIZE=W,H` sets the window.
- `node tools/trace.mjs [filter] [ports]`: lockstep race scenarios, ports enabled vs original. E.g. `node tools/trace.mjs '' src/car.js` or `... '' math,update_grip`. Scenarios live in `SCENARIOS` (exported, so test files can push their own).
- `tools/dseg-labels.mjs` and `tools/procmap.mjs` regenerate `src/dseg-labels.js` and `src/procs.js` from ref/restunts; `node tools/vermap.mjs game-ms --write` regenerates the Mindscape tables from them.
